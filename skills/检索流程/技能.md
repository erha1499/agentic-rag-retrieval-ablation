# 按场景选择检索方法

先判断需要文档规则、源码实现，还是两者，以及所需材料的范围。工具是否可用，以当前工具清单为准。

语料以英文为主。面对中文问题，在当前工具调用中自行构造英文检索词：`grep` 使用英文关键词、代码符号或正则，`rag_search` 使用英文语义描述并保留必要术语。无需额外调用模型翻译，也无需让用户补充英文术语。首次命中不足时，可调整同义词或查询范围。

1. **校验逻辑和代码细节**：用 `grep` 定位函数、变量、错误文本或相关条件，再用 `read_file` 按行读取必要代码。核对实际分支、返回值和调用关系，不能从名称推断实现。仅问文档规则时，无需扩展源码分析。
2. **文档少或目标文件小**：定位后可用 `read_file` 全文读取。需要了解文件大小时，`grep(files_only=true)` 会返回路径、字符数和行数。正文返回上限为 12000 字符，包含行号；超过时按行分段读取。
3. **文档多、问题只需局部内容**：已知准确术语或章节时，用 `grep` 定位，再按行补读上下文。术语不明确时，若有 `rag_search`，可用自然语言检索相关文档片段，例如 `scope=doc, top_k=3`，再按需要补读适用条件和例外；也可用关键词或同义词检索。无需固定采用同一种方法，也无需调用所有可用工具。
4. **文档与源码联合问题**：查明文档规则，再定位实现并核对条件与执行顺序。RAG 命中源码可帮助定位，精确代码条件用 `grep` 或按行读取确认。
5. **全局概览或完整性问题**：定位目录、章节或函数边界，连续读取并核对覆盖范围。少量检索命中不能证明完整；搜索无命中也不能证明相关能力不存在。

只取回答问题所需的材料，证据充分后结束检索。工具报错时修正参数；材料不足时说明已查范围和缺口。
