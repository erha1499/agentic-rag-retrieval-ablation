# 智能体如何检索资料并使用工具

本项目使用手写 Python 单 Agent 循环。每个问题、每个组分别建立消息历史，不继承上一题内容。

初始消息包含[系统提示词](../prompts/系统提示词.md)及用户问题。共同检索流程直接写入系统提示词，不注册独立的 Skill 加载工具。

运行器只提供下表列出的工具，不自动继承宿主 Codex 的系统提示词、技能或其他工具。

## 实际循环

1. 从第一轮开始提供该组的检索工具，由模型根据问题选择检索和读取方法。
2. 只执行本轮实际提供的工具，未提供的工具调用会被拒绝。工具结果进入消息历史，再调用模型。
3. 若返回回答，检查引用格式及其行范围是否实际读到；通过后结束。输出截断或引用检查失败时，最多反馈一次，仍占用原有调用额度。

修正时允许继续检索或按行补读，仍共享原有轮数、时限与预算；只有最后一轮禁用工具，不额外增加修正次数。引用位置检查不判断内容是否正确或支持结论，语义正确性另行评审。

## 工具与共同限制

| 组别 | 注册工具 |
| --- | --- |
| A | `grep`、`read_file` |
| B | `grep`、`read_file`、`rag_search` |

两组使用相同系统提示词、模型和限制。模型自主决定检索方法；B 没有调用 RAG 的任务仍属于 B。

每个任务最多 8 次主模型交互，每次输出最多 1200 token。检索、读取及回答修正均共享这 8 次额度，没有免费附加轮次。第 8 轮不提供工具，只根据已收到的证据作答；即使返回工具调用，也不会执行。

`read_file` 每次返回最多 12000 字符，包含行号；超出时报错，不静默截断。`rag_search` 的父块正文预算默认 12000 字符，由配置的 `rag_return_char_budget` 控制；向量候选数、关键词候选数、RRF 常数和精排候选数也读取配置。`grep` 按命中数和上下文行数限制返回，最多 200 个命中、每侧最多 20 行上下文，没有统一的 12000 字符上限。

文档和源码正文可构成引用证据；系统提示中的操作指导和工具返回的文件列表不能代替正文引用。

当前配置为非思考模式、温度 0、单任务串行，任务时限 180 秒。时限在循环和工具调用边界检查，不能立即中断已发出的 HTTP 请求。配置来源为[实验配置](../experiment_config.json)，运行实现见[运行器](../run_experiment.py)。
