# 智能体如何加载技能并使用工具

本项目使用手写 Python 单 Agent 循环。每个问题、每个组分别建立消息历史，不继承上一题内容。

初始消息包含[系统提示词](../prompts/系统提示词.md)、运行器追加的技能名称与描述、技能加载方式，以及用户问题。初始系统消息不包含检索 Skill 正文。模型调用 `load_skill(name="检索流程")` 后，正文作为工具结果进入当前消息历史；具体策略只维护在[检索技能](../skills/检索流程/技能.md)中。

这是本项目运行器注册的技能，不安装到宿主 Codex，也不自动继承 Codex 的系统提示词、技能或其他工具。

## 实际循环

1. 调用 Qwen Plus，由模型决定调用工具或回答。
2. 若返回工具调用，依次执行，将结果加入消息历史，再调用模型。
3. 若返回回答，检查引用格式及其行范围是否实际读到；通过后结束。输出截断或引用检查失败时，最多反馈一次，仍占用原有调用额度。

修正时，尚未取得正文证据的会话可以补检索；已有正文的只修改回答。引用位置检查不判断内容是否正确或支持结论，语义正确性另行评审。

## 工具与共同限制

| 组别 | 注册工具 |
| --- | --- |
| A | `load_skill`、`grep`、`read_file` |
| B | `load_skill`、`grep`、`read_file`、`rag_search` |

两组使用相同系统提示词、技能正文、模型和限制。模型自主决定检索方法；B 没有调用 RAG 的任务仍属于 B。

每个任务最多 8 次主模型交互，每次输出最多 1200 token。发起技能加载的交互及加载后的后续交互均在这 8 次内，没有免费附加轮次。`load_skill` 是本地读取，不单独调用模型服务；模型发起调用及后续读取技能上下文产生的 token 费用照常计入。

`read_file` 每次返回最多 12000 字符，包含行号；超出时报错，不静默截断。`rag_search` 的父块正文预算默认 12000 字符，由配置的 `rag_return_char_budget` 控制；向量候选数、关键词候选数、RRF 常数和精排候选数也读取配置。`grep` 按命中数和上下文行数限制返回，最多 200 个命中、每侧最多 20 行上下文，没有统一的 12000 字符上限。

文档和源码正文可构成引用证据。技能正文是操作指导，`load_skill` 不产生已读证据行，不能用来代替文档或源码引用。

当前配置为非思考模式、温度 0、单任务串行，任务时限 180 秒。时限在循环和工具调用边界检查，不能立即中断已发出的 HTTP 请求。配置来源为[实验配置](../experiment_config.json)，运行实现见[运行器](../run_experiment.py)。
