## 未通过的原因

1. **共同 Skill 没有实际加载。** 4/4 均未调用 `load_skill`，尽管系统要求先加载适用技能。轨迹使用了英文术语，但不能把这种行为归因于 Skill 生效。
2. **源码定位后缺少完整上下文。** 多次把 `|` 当作 `path_glob` 的路径并集，并遗漏语料路径前缀，导致零命中。A 的一次整文件读取超过字符上限，未改成按行补读；B 的一次正则因未转义 `{` 报错。两组均未成功按行读取休眠函数的完整等待循环。
3. **源码题存在重要错误。** 两组都声称配置重载不会唤醒休眠；`misc.c` 第 382—385 行明确说明非取消信号如 SIGHUP 可以提前结束一次等待，而第 389—410 行通过目标时间和剩余等待重算保证总休眠不因此缩短。两组还混淆了部分调用或信号处理位置。引用的行确实读过，也不足以支持这些扩展断言。
4. **信息不足题没有回答部署决策。** 两组首次无正文证据直接作答，修正后主要变成已检索事实清单，未澄清部署资源、连接或查询负载和测量需求，也未完整说明提高最大连接数与共享内存等资源分配的关系。B 的一条引用把两个行范围写进同一对括号，修正后仍未通过格式检查。

评审保留了轻微引用边界偏差：已收到的上下文可支持部分附带陈述，但不能补齐缺失必要事实，也不豁免无效复合引用。另修正过一项评分结构矛盾：某必要事实未完整覆盖，不能同时标为完整事实有证据支持；原严格不通过结论未改变。未发现冻结金标准错误，未重跑或替换任何模型答案。
