# 如何运行与控制费用

当前入口直接读取 `data/cases_dev.json` 和 `data/cases_test.json`，共 2 道开发题、6 道正式题。系统提示词为 `prompts/系统提示词.md`，检索方法集中在 `skills/检索流程/技能.md`。当前版本尚未调用真实模型，历史成绩不能沿用。

## 离线检查

需要 Python 3.12+、ripgrep，以及 `requirements.txt` 中的依赖。以下检查使用临时材料和假客户端，不请求模型：

```sh
python3 test_qwen_client.py
python3 test_runner.py
python3 test_evidence.py
python3 test_evaluation.py
python3 build_corpus.py --self-test
```

重点验证技能按需加载、A/B 共同能力一致、语料引用边界、账本预算、配置指纹及旧结果隔离。它们不证明模型能正确选择工具或生成正确答案。

## 运行前确认

`freeze_manifest.json` 记录当前源文件、题集、系统提示词、Skill、配置与语料索引的 SHA256。执行器在创建付费客户端之前逐项核验，并将清单指纹绑定到 `runs/实验标识.json`。评审和汇总也核对同一指纹；文件改变、旧目录没有归属标识或指纹不符时拒绝继续。

提示词、Skill 和题集可以直接覆盖维护，历史源文件由 Git 保存。已有运行数据时修改输入，应先完整归档其轨迹、账本、盲评和冻结清单，再为当前源文件更新清单；不得只重写旧目录里的标识来绕过检查。正在运行或在途的任务需先核实状态，不能直接清除。

本地历史改进轮已移到 `local_history/改进轮/runs/`，旧清单和归档校验记录在同级目录；首轮在 `local_history/首轮/`。这些原始证据未提交 Git，不应删除后仅依赖 Git 恢复。

## 模型调用与预算

模型与限制见 `experiment_config.json`：Qwen Plus，非思考模式，温度 0；每题最多 8 次主模型交互、每次输出最多 1200 token，单并发。`load_skill` 在本地执行，没有独立模型请求；模型选择加载技能的交互占用调用轮数，返回的技能文本作为后续输入计费。查询向量、精排和 HTTP 重试同样记入费用。

配置中的 3 元是总支出保护上限，复用已有索引，不包含首次建库。本次只修改和离线验证，没有启动付费实验。后续执行前应确定实际可用支出上限，不能把历史预算余额自动视为当前运行授权。

通过安全环境提供 `DASHSCOPE_API_KEY` 与 `DASHSCOPE_BASE_URL`，不写入仓库。确认预算与输入清单后执行：

```sh
python3 run_experiment.py dev --workers 1
python3 run_experiment.py test --workers 1
```

请求前预留保守费用上界，按返回 usage 结算。失败或未知用量不能当作零；预算不足或无法确定有效上界时停止后续任务。已有终态任务跳过，失败也保留，不因答案不好而追加运行。费用是公开价估算，不等于账单核实金额。

## 评审与输出

```sh
python3 prepare_review.py --split test
# 按 discuss/评分规则.md 逐项评审，写入 runs/review/review_*.json
python3 summarize.py --split test
```

模型只收到题目正文、系统提示、实际加载的 Skill 和工具返回。金标准、题型难度、参考实现与历史答案不传给模型。引用位置校验不判断语义，评审仍须检查原文支持。

原始记录保存在 `runs/`，脱敏结果输出到 `results/当前实验/正式/` 或 `results/当前实验/开发/`，便于阅读的副本在 `outputs/`。开发结果不混入正式分母。未执行时报告 `not_started`，不生成虚假的零分或通过率。

## 语料与索引

当前 `data/` 中的语料和索引通过项目内相对链接复用首轮材料，禁止原地重建。公开仓库不包含原始语料、向量和凭据。克隆后需要匹配的语料、块清单及索引，或者在独立目录另行规划建库预算。
