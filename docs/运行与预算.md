# 如何运行与控制费用

当前入口直接读取 `data/cases_dev.json` 和 `data/cases_test.json`，共 2 道开发题、6 道正式题。共同检索流程直接写入 `prompts/系统提示词.md`，A 使用 `grep`、`read_file`，B 额外提供 `rag_search`。本次将主指标调整为总在线成本与降本率，质量不降低作为约束，不要求质量提升。新口径尚未启动模型调用；历史[开发集冒烟报告](开发集冒烟报告.md)及 `results/` 中已有结果保留原口径，不改写成绩。

## 离线检查

需要 Python 3.12+、ripgrep，以及 `requirements.txt` 中的依赖。以下检查使用临时材料和假客户端，不请求模型：

```sh
python3 test_qwen_client.py
python3 test_runner.py
python3 test_evidence.py
python3 test_evaluation.py
python3 build_corpus.py --self-test
```

重点验证 A/B 共同能力一致、修正中补读、语料引用边界、账本预算、检索参数生效、在途状态、配置指纹及旧结果隔离。它们不证明模型能正确选择工具或生成正确答案。

## 运行前确认

`freeze_manifest.json` 记录当前源文件、题集、系统提示词、配置与语料索引的 SHA256。执行器在创建付费客户端之前逐项核验，还会按照 `data/files.jsonl` 核对语料文件集合和每个文件正文的 SHA256，拒绝正文修改、文件增删和越界链接。语料根目录允许使用项目内链接，内部目录链接不接受。核验通过后，将清单指纹绑定到 `runs/实验标识.json`。评审和汇总执行相同核验；旧目录没有归属标识或指纹不符时拒绝继续。

提示词和题集可以直接覆盖维护，历史源文件由 Git 保存。已有运行数据时修改输入，应先完整归档其轨迹、账本、盲评和冻结清单，再为当前源文件更新清单；不得只重写旧目录里的标识来绕过检查。正在运行或在途的任务需先核实状态，不能直接清除。

本地历史改进轮已移到 `local_history/改进轮/runs/`，旧清单和归档校验记录在同级目录；首轮在 `local_history/首轮/`。这些原始证据未提交 Git，不应删除后仅依赖 Git 恢复。

2026 年 10 月 17 日首次开发冒烟位于 `local_history/开发冒烟/`，精简流程后的复测已完整归档至 `local_history/检索流程复测/`，其中包含原始轨迹、账本、评分、冻结清单、配置、报告和结果副本。新目录仅绑定新口径，不能混入旧调用或评分。

## 模型调用与预算

模型与限制见 `experiment_config.json`：Qwen Plus，非思考模式，温度 0；每题最多 8 次主模型交互、每次输出最多 1200 token，单并发。检索流程直接作为共同系统提示输入，检索、读取和回答修正共享原有轮数，最后一轮禁用工具，没有免费附加轮次。查询向量、精排和 HTTP 重试同样记入费用。

自 2026 年 10 月 19 日起，后续新增 Qwen 调用的总硬上限为 20 元，覆盖开发与正式任务、查询向量、精排、失败及重试。复用已有索引，不重建索引，20 元不必花完。首次开发冒烟公开价估算 0.0663261 元，精简流程复测 0.1132240 元，两次合计 0.1795501 元，单列为此前支出，不扣减这次新增的 20 元，也不复制到新账本。该合计不是整个项目的历史总投入，首轮、改进轮和建库费用仍保留各自记录；公开价估算不等于已核实账单。本次只调整预算、计划和离线检查，不启动模型请求，不恢复旧暂停实验。

建议开发检查分配 2 元、正式对比分配 8 元，其余 10 元预留且不自动使用。代码只硬控制 20 元总额，阶段金额是建议分配，尚无独立阶段限额；达到阶段建议额度或进入下一阶段前，需要检查账本、结果和剩余预算，不因余额充足扩题、加轮或重复追分。

通过安全环境提供 `DASHSCOPE_API_KEY` 与 `DASHSCOPE_BASE_URL`，不写入仓库。后续先依据已归档开发轨迹离线收敛引用格式与额外无依据断言，再确认接口权限、价格、预算与输入清单。若只改变预算或指标、没有实际行为修复，先复核已有轨迹，不为口径变化重复付费。确需验证修复时，运行 2 道开发题的 A/B，共 4 个任务：

```sh
python3 run_experiment.py dev --workers 1
```

开发完成后先评审并汇总，命令中的人工评审步骤不可跳过：

```sh
python3 prepare_review.py --split dev
# 按 discuss/评分规则.md 逐项评审，写入 runs/review/review_*.json
python3 summarize.py --split dev
```

检查任务与费用记录完整、证据和引用可追溯，并逐题检查质量是否退化。启动正式对比不要求双方严格全对，不强制 B 使用 RAG；若有关键流程失败、预算异常或质量退化，停在开发阶段处理，不连续重跑追分。开发检查通过后固定正式输入，再执行 6 道正式题的 A/B，共 12 个任务，保留低、中、高难度各 2 道：

```sh
python3 run_experiment.py test --workers 1
```

请求前预留保守费用上界，按返回 usage 结算。失败或未知用量不能当作零；预算不足或无法确定有效上界时停止后续任务。已有终态任务跳过，失败也保留，不因答案不好而追加运行。费用是公开价估算，不等于账单核实金额。

## 评审与输出

```sh
python3 prepare_review.py --split test
# 按 discuss/评分规则.md 逐项评审，写入 runs/review/review_*.json
python3 summarize.py --split test
```

模型只收到题目正文、共同系统提示和工具返回。金标准、题型难度、参考实现与历史答案不传给模型。引用位置校验不判断语义，评审仍须检查原文支持。

## 成本主指标与质量约束

主指标为所选开发或正式集合全部任务的在线降本率 `1 - B总费用/A总费用`。正数表示省钱，负数表示增费；包含失败、重试、查询向量和精排，B 未调用 RAG 的任务照常计入。开发和正式分别报告，不合并分母；建库与更新成本另列，按预计复用量摊销，不据在线降本直接宣称总投入已回本。

汇总新增以下字段：

- `primary_metric` 为 `online_cost_saving_rate`；`cost_quality_comparison.cost` 提供 A/B 总费用上下界及降本率。未完成配对任务或 A 基准费用为零时不计算点估计。
- 用量未知时只提供可确定的费用及降本率区间；在途请求或费用未报时不宣布降本成立。`费用未报请求` 在逐题 CSV 和分组汇总中单列，不能把明确拒绝但未报 usage 的请求当成确定免费。
- `cost_quality_comparison.quality_pairs` 逐题检查正确事实和证据支持是否丢失、来源或引用是否退化、重要错误是否增加。B 仍有重要错误且数量未增加时标记 `needs_review`，不能靠错误数量推定质量相同。
- `cost_quality_comparison.conclusion` 只有在全部任务双方完成、可评分、已评审、费用已知且已测质量维度未观察到退化时，才报告 `cost_reduction_observed_under_quality_guardrail`。双方绝对严格通过可以均为 false，不要求全对或准确率提升。
- `cost_quality_by_scenario` 按预先标注的场景报告相同口径，保留所有题，不能只展示 RAG 获胜的子集。

这些是当前小样本的描述性观察，不是统计非劣或未来质量保证。原有逐事实、重要错误、引用和严格通过尺度保留，不因切换主指标而放宽。详细规则见[缩量实验方案](../discuss/缩量实验方案.md)和[评分规则](../discuss/评分规则.md)。

原始记录保存在 `runs/`，脱敏结果输出到 `results/当前实验/正式/` 或 `results/当前实验/开发/`，便于阅读的副本在 `outputs/`。开发结果不混入正式分母。没有 API 结算记录且没有在途请求时报告 `not_started`，不生成虚假的零分或通过率。仅有费用预留、尚未结算时报告 `in_flight`，表示请求在途或执行情况未知，保留费用上界；预留本身不计入已确认执行分母，也不计终态和配对胜负。有此前已确认请求的任务仍计已执行，但在途期间不算终态。

检索器从 `experiment_config.json` 读取 `vector_top_k`、`keyword_top_k`、`rrf_k`、`rerank_candidate_count`、`rag_return_char_budget`，分别控制向量候选数、关键词候选数、RRF 常数、精排候选数和返回正文字符预算。参数须为整数，RRF 常数可为零，其余必须大于零。用户问题保留自然中文；共同系统提示指导 Agent 在原有工具调用中构造英文查询，不增加独立翻译请求。本次未改模型、提示词、题目或检索参数。
