# 当前缩量实验方案

目标是在回答质量不降低的约束下，检验增加 `rag_search` 是否降低总在线成本。准确率或回答质量提升不是成功的必要条件。A 使用 `grep`、`read_file`；B 额外提供 `rag_search`。两组共用同一 Agent、系统提示词及其余条件，不强制 B 使用 RAG。运行机制见[智能体运行说明](../docs/智能体运行说明.md)，共同检索流程直接维护在[系统提示词](../prompts/系统提示词.md)。

## 题集与对照

当前默认题集为 Q01—Q06 六道正式题和两道开发题。正式题按低、中、高难度各设计两道，按实际意图分为四道使用问答和两道源码阅读；每题 A/B 各运行一次，计划共 16 个任务。各会话独立，仅将问题正文交给模型，不提供金标准、类型或难度标签。

题干采用自然问法，证据与内部实现说明留在评分资料。它们是已知题目的改写，不是全新独立样本；表达变化也可能改变实际检索难度。历史答案和评分不能作为当前题目与提示词版本的成绩。

## 判断收益

主指标为同一冻结任务集合的 A、B 总在线费用及降本率：`降本率 = 1 - B 总在线费用 / A 总在线费用`。A 总费用为零时不计算比率。费用包括主模型输入与输出、查询向量化、精排、重试及失败请求；开发费与正式费分列，预算仍累计计算。工具次数、RAG 使用率、输入 token 和耗时只用于解释成本变化。

总体比较保留全部计划任务，包括 B 未使用 RAG、运行失败和未完成的任务；不得只保留两组答对或 RAG 获胜的题。单边未执行、在途、费用未知及质量未评审必须另列，不能把缺失记作零费用并直接判定降本成功。费用未知时展示上下界，不作完整结果的成功判定。

质量仍按[评分规则](评分规则.md)逐题检查，保留原有事实、引用、来源和重要错误标准。保守观察门槛为：每项必要事实的“覆盖且正确”和“有支持”均不能由 A 的 true 退为 B 的 false；一项事实的改善不能抵消另一项退化，删除原本答错的内容不单因覆盖变少而判退化。A 满足的来源、引用、完成和可评分要求，B 也须满足。B 的重要错误数增加视为退化；数量未增加但 B 仍有重要错误时，须逐对审裁错误性质和严重程度，不能自动宣称未退化。未知质量保持未知。两组严格通过数相同，或双方均未严格通过，不能据此认定质量相同；也不要求双方绝对全对后才比较成本。

全部计划任务双方均完成、有可评分答案且已评审，费用已知且无在途，完整任务集合费用更低，逐题已测维度未观察到质量退化，才报告“当前样本在已测质量维度未观察到退化，且在线费用降低”。仍需审裁的重要错误不自动通过。逐题门槛是保守的描述性检查，不是统计非劣或等效证明。按难度和任务类型查看配对个案，但每层仅两题，不能据此声称统计显著或跨数据库普适。

既有建库费用与后续更新费用单列，不混入每次在线调用，也不能忽略它们后宣称总投入回报已证明。可按预计复用请求数 N 展示 `B 摊销费用/题 = B 平均在线费用/题 + 建库及更新费用/N`；费用或复用量未知时保留未知，不给出确定回本结论。本地计算和评审成本未折算人民币，应保留这一限制。
