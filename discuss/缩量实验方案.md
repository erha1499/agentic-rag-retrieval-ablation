# 按场景选择检索方法的缩量实验方案

本轮验证一套共同的检索流程：代码细节先定位源码并读相关行；短文档可全文阅读；大文档中只需局部知识时，允许 Agent 自主调用混合检索工具。目标是确认这套流程可执行，以及在此基础上增加 Agentic RAG 的质量、费用与耗时增量。未经运行与评审，不预设 RAG 一定有效。

A 组可用 `grep` 与文件读取；B 组保留 A 的全部工具，并增加 `rag_search`。两组使用同一主模型、共同提示、区间读取能力、答案格式和调用限制。组间唯一差异是是否提供 `rag_search`。本轮对两组共同修改提示和读取能力，因此本轮与历史首轮的质量或费用差异不能单独归因于 RAG。

## 检索流程

1. 先判断需要官方行为说明、代码实现核验，还是两者的联系。把必须回答的条件列成最多三项；明确函数、错误文本、配置名等精确标识。
2. 核验条件分支、权限检查、边界行为或调用链时，优先用 `grep` 找到函数与调用者，再读取相关代码区间。必须核实实际代码，不以文档或检索摘要替代代码结论。即使由 RAG 找到位置，也需要阅读该源码区间确认条件和上下文。
3. 文档短且相关内容占比较高时，读取全文；明确只需要某个局部规则时，可先按关键词定位再读相邻区间。长文档不默认全文塞入模型。
4. 文档量大、自然语言需求难以形成精确关键词，而且只需少量相关内容时，B 组可用 RAG 定位。先选合适的范围与较小返回量；引用前回看原文，必要时增加邻近区间。A 组使用关键词和目录线索逐步定位。
5. 检索为空或结果不一致时，先改变关键词或缩小文件范围，再决定是否换检索方式。避免无方向重复调用。用更多工具调用本身不算成功。
6. 回答前核对每个必要结论都有实际收到的原文支持。源码题引用源码，联合题引用文档和源码。答案保持简短，只回答所问条件；材料不能支持时说明缺口，不扩写推测实现。

以上是选择依据，不是“代码永远不用 RAG”或“长文档永远不用 grep”的硬规则。精确标识通常适合关键词；语义问题通常适合混合检索；全文适用于可承受的小材料。路由是否合适要结合实际工具轨迹判断。

## 样本与难度

开发集两题，每题 A/B 各一次；正式集六题，每题 A/B 各一次，总计最多 16 次任务。正式集低、中、高难度各两题；文档、源码、联合题各两题。排队次序按低、中、高交错；A/B 先后交错，所有会话独立。

| 题号 | 难度 | 类型 | 所测场景 | 参考出处规模 |
| --- | --- | --- | --- | --- |
| N01 | 低 | 文档 | 同名保存点的遮蔽与释放，适合短页全文 | 399 英文词、109 行 |
| N02 | 中 | 文档 | 长 ALTER TABLE 文档中 NOT VALID 的局部规则 | 8,104 英文词、974 行 |
| N03 | 高 | 联合 | 冲突更新 WHERE 为 false 时的锁与返回，文档和执行器核验 | 文档 2,986 英文词；源码 4,759 行 |
| N04 | 低 | 源码 | 给定函数名，精确核验列集合和锁模式条件 | 源码文件 3,037 行 |
| N05 | 中 | 源码 | 终止信号到等待辅助函数的短调用链 | 源码文件 291 行 |
| N06 | 高 | 联合 | WITH TIES 的文档语义与执行边界处理 | 文档 10,549 英文词；源码 558 行 |

正式集共 16 个必要事实，每题仅两到三个；题干未要求的细节不追加为通过条件。难度是本轮预先指定的相对难度，不是经过大样本人类测定的客观等级。小样本刻意覆盖场景，不能视为总体随机抽样。

至少一个必要出处来自 3,000 英文词文档页或 3,000 行源码文件时，记为长材料题；本轮为 4/6。词数包括示例、表格和标识符，代码行数包括注释和空行。长度不是要求 Agent 必须读取的数量。

P01 开发题核验 `pg_sleep` 的可中断等待和截止时间计算；P02 仅校验材料不足时不编造生产配置值。P02 不进入正式效果分母。正式题全部是可由当前材料回答的问题。

题目均独立新编，作者只查原文及历史题干，没有读取历史 Agent 答案。N01、N03、N06 与历史题有相邻主题或共用文件，所问事实不同；具体重叠已在 `data/case_manifest.json` 披露。被测 Agent 仅接收题号、类型与问题，不接收金标准、场景或难度标签。

## 预算与停止条件

本轮后续 Qwen 调用保守计费上限为人民币 3 元，开发、正式、查询向量化、精排和失败重试全部计入。已有完整索引直接复用，不重复建库；历史投入单列，不从本轮增量预算中扣除，也不隐藏。

初拟两组共同限制为：每任务最多八次主模型调用，每次输出最多 1,200 token，任务限时 180 秒，单并发。应先在开发集确认输出可完整结束、证据能回核、预算预留真实；如需修复流程，在正式启动前明确记录并冻结最终参数，不依据正式答案继续调参。正式前独立验题并冻结题集、共同提示、工具、模型快照、限制和价格口径。

调用前预留保守费用上界；未知用量与失败请求不自动按零元处理。剩余预算不足以覆盖下一次调用上界时，停止新增调用，保留已执行、失败、未执行任务及在途预留。不得缩小计划分母、换题或为追求更好答案重跑后称“完整完成”。账户余额不代替本轮 3 元硬上限。

## 如何评估

正式主指标为六题中“完成、必要事实正确且原文支持”的任务数；同时报告完成率、必要事实覆盖、引用支持和重要错误。无答案、失败、未执行分别保留。只看有利题或只看 B 实际调用过 RAG 的题不能替代整体 A/B 分母。

隐藏组别评审逐项核对必要事实与收到的原文；允许有效替代证据，不强求金标准同一行。报告评审方式及复核范围，不将代理评审称为独立人工评测。

费用分别列出 A/B 在线公开价估算、开发费用、失败和未知费用区间；耗时用中位数并保留逐题记录。记录每题首选方法、检索切换、全文/区间读取、RAG 是否调用、调用次数和返回字符数。RAG 首选后转向 grep 核验代码可以是合理流程；工具数量少或 RAG 使用率高本身不是目标。

按难度和任务类型给出配对结果，并描述路由是否符合所需证据。各分层只有两题，只做个案观察；不能据此宣称统计显著、跨数据库普适或单独证明向量、RRF、rerank 某组件有效。源码未实际编译运行、数据库未部署，结论范围限于固定版本材料上的检索问答与实现阅读。
