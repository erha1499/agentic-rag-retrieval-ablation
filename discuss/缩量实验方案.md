# 当前缩量实验方案

目标是在同一 Agent、系统提示词和检索 Skill 下，比较增加 `rag_search` 后的回答质量、在线费用与耗时。A 使用 `load_skill`、`grep`、`read_file`；B 额外提供 `rag_search`。其余条件一致，不强制 B 使用 RAG。运行机制见[智能体运行说明](../docs/智能体运行说明.md)，检索策略只维护在[检索技能](../skills/检索流程/技能.md)。

## 题集与对照

当前默认题集为 Q01—Q06 六道正式题和两道开发题。正式题按低、中、高难度各设计两道，按实际意图分为四道使用问答和两道源码阅读；每题 A/B 各运行一次，计划共 16 个任务。各会话独立，仅将问题正文交给模型，不提供金标准、类型或难度标签。

题干采用自然问法，证据与内部实现说明留在评分资料。它们是已知题目的改写，不是全新独立样本；表达变化也可能改变实际检索难度。历史答案和评分不能作为当前题目、提示词或 Skill 版本的成绩。

## 预算与启动条件

配置中的总预算上限为 3 元，覆盖开发与正式任务、查询向量化、精排和失败重试；复用既有索引。每任务最多 8 次主模型交互、每次输出 1200 token、时限 180 秒、单并发。发起技能加载及加载后的交互计入相同上限，技能上下文产生的模型 token 费用照常计入。

当前版本尚未运行。本次仅整理题集、提示词、Skill 和代码，不执行付费调用；配置中的 3 元上限不表示新增开跑授权。

后续启动前需确认开发集流程可用，并固定题集、提示词、Skill、工具实现、模型与参数、价格口径。正式运行后不依据正式答案调参或换题。调用前预留保守费用上界，预算不足或无法确定有效费用上界时停止新增调用，保留失败、未执行及在途记录。

## 判断收益

逐题核验必要事实是否正确、实际收到的原文是否支持答案，并保留重要错误。报告每组计划、执行、完成和正确有支持的数量，分别列出失败、无答案及未执行任务；B 未使用 RAG 的题仍计入 B。评分允许有效替代证据，不强求与参考证据相同行号。

同时比较 A/B 在线公开价估算、开发费、失败及未知费用、耗时和工具轨迹。技能加载次数单列，其上下文费用包含在模型总费用中；不用 RAG 使用率或工具次数代替效果。按难度和任务类型查看配对个案；每层仅两题，结果只用于判断是否值得继续，不能据此声称统计显著或跨数据库普适。
